# remittance-stablecoin

A Token-2022 remittance stablecoin on Solana (Anchor 0.30.1), built for the
Turbin3 Token-2022 homework. It stacks mint extensions from an on-chain program
and tests how a compliance feature (`PermanentDelegate`) interacts with a
privacy feature (`ConfidentialTransferMint`). Write-up: [docs/FINDING.md](docs/FINDING.md).
Post draft: [docs/X-POST.md](docs/X-POST.md).

## What was built

Program instructions (`programs/remittance-stablecoin/src/lib.rs`):

| Instruction | What it does |
|---|---|
| `init_mint_v1` | Creates a mint with the v1 extension stack (below) |
| `init_mint_v2` | v1 stack + PermanentDelegate + confidential transfer (manual approve) |
| `transfer_with_fee` | `transfer_checked_with_fee` CPI; the caller's `expected_fee` must equal the mint's epoch fee (mint read via `StateWithExtensions`) |
| `thaw_account` | Freeze-authority thaw of one account; other new accounts stay frozen |
| `deposit_confidential` | CPI `Deposit`: public balance to confidential pending balance |
| `apply_pending_balance` | CPI `ApplyPendingBalance`; the client supplies the credit counter and AES ciphertext |
| `delegate_transfer` | Transfer through a program PDA delegate (`seeds = ["delegate"]`, `invoke_signed`); still works after the user turns on CPI Guard |

### Extension stack

| Extension | v1 | v2 |
|---|---|---|
| TransferFeeConfig (50 bps, 1 token cap) | yes | yes |
| MetadataPointer (points at the mint) + TokenMetadata | yes | yes |
| DefaultAccountState = Frozen | yes | yes |
| MintCloseAuthority | yes | yes |
| PermanentDelegate (issuer) | no | yes |
| ConfidentialTransferMint (`auto_approve_new_accounts = false`, no auditor) | no | yes |
| ConfidentialTransferFeeConfig | no | yes (Token-2022 requires it whenever a fee mint is also confidential) |

Extensions cannot be added to an existing mint, so v2 is a new mint address;
see the migration section in [docs/checkpoint-3.md](docs/checkpoint-3.md).

## Run it

Needs: Anchor 0.30.1 via avm, Solana CLI 4.2.2 (for `solana-test-validator`),
`spl-token` CLI 5.6.1 on `PATH`, `yarn install` done.

```
~/.avm/bin/anchor-0.30.1 build
~/.avm/bin/anchor-0.30.1 test
```

Known flake: right after a previous run, the validator sometimes does not
start ("Test validator does not look started"). Wait a few seconds and rerun.

Last full output: [docs/test-output.txt](docs/test-output.txt).

## Finding, in short

`PermanentDelegate` can only move the plaintext balance. A holder who deposits
into the confidential balance first puts funds where the delegate cannot build
the required ZK proofs. Controls belong before the deposit: manual account
approval (deposit before approve fails with `0x18`), frozen-by-default
accounts, freeze on suspects, monitoring plaintext `Deposit` amounts, and an
auditor ElGamal key at mint init (not set in this repo). Full write-up:
[docs/FINDING.md](docs/FINDING.md).

## Tooling limitations

- **Confidential transfer on a fee mint is not supported by the tooling.**
  spl-token CLI 5.6.1 panics with "Confidential transfer with fee is not yet
  supported", and `@solana/spl-token` 0.4.15 has no confidential-transfer
  client. The v2 mint has a transfer fee, so the ZK-proof transfer is
  demonstrated on a control mint without the fee extension. The v2 lifecycle
  test covers configure, approve, deposit, apply pending, and withdraw.
- **The ZK steps shell out to `spl-token`.** There is also no JS decrypt
  helper, so decrypted balances are checked black-box: withdrawing the exact
  amount succeeds, one unit more fails.
- **Mainnet Token-2022 genesis fixture.** The Token-2022 built into
  solana-test-validator 4.2.2 is compiled without the `zk-ops` feature, so
  confidential Deposit, Withdraw, Transfer and ApplyPending all return
  `InvalidInstructionData`. `Anchor.toml` overrides it with a dump of the
  mainnet program (`tests/fixtures/token_2022_mainnet.so`, dumped 2026-09-30 with
  `solana program dump -u m TokenzQdBNbLqP5VEhdkAS6EPFLC1PHnBqCXEpPxuEb`).
- The ElGamal pubkey used for the confidential fee config is a public key
  generated by the CLI; its secret is not kept, so withheld confidential fees
  on that test mint cannot be withdrawn.
